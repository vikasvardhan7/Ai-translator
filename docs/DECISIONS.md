# Decisions

Agreed product and technical decisions. Newest first. Change only with the owner's approval.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-20 | Other websites and apps use the translator with API keys made in the Developers app: a one-line widget for websites (the app's own page in an iframe) and the REST and WebSocket API for servers. Keys are kept in `backend/data/keys.db` as SHA-256 fingerprints only, each with its own daily limit; keys, invited guests and every sentence of a key's conversations are counted in memory (60 a minute for keys, 20 a minute and 400 a day for guests, none for the host) and answered with `429` and `Retry-After` past the limit. Keys never manage keys or meetings. | Makes the translator usable from any app without sharing the host key, and stops one app or one leaked link from using up the free Gemini quota. |
| 2026-10-20 | A busy or unreachable Gemini is tried again up to three times with growing waits (0.5, 1, 2 s, or Gemini's own suggested wait up to 8 s; 12 s in all) instead of once. | One retry still dropped sentences when the free tier was busy for a few seconds. |
| 2026-10-19 | Meetings can be scheduled: title, start, length, agenda and the host's name are kept in a small SQLite file on the laptop (Python's own `sqlite3`, no new dependency), never audio, captions or transcripts, and are dropped a week after they end. The link is sent by the host (copy, share, email through their own mail app, calendar file); the app sends nothing itself. Guests who come early wait in a lobby and join when the host starts. | People asked to plan meetings with a time, length and agenda and send the link ahead. Sending email from the app would need a mail account and a paid or configured service. |
| 2026-10-19 | The desktop names what each start does: Meet now (a meeting others join with a link), Schedule, Live captions (for Zoom, Teams or Meet) and Talk here (one device). | "Call another device" and "Person 1 / Person 2" did not say what the options were. |
| 2026-10-19 | Calls across devices take up to 6 people through one invite link. The host enters the call at once and shares the link from inside it; each guest gets the next id (`B` to `F`) and their own device token; the invite token only joins. A guest who leaves does not end the call and their place is never reused, so transcript names stay right; the host leaving ends it for everyone. Each sentence is translated once into every language in the call. | People asked for a meeting link others can join, like a normal call. Voice and captions only: video needs WebRTC and, on some networks, a paid relay. |
| 2026-10-19 | When the speaker is known (their own device in a call, or the microphone in a meeting), their chosen language goes to Gemini as a hint with each sentence. | Fewer wrong words and wrong languages; the speaker can still switch language. |
| 2026-10-19 | Five looks (Ocean, Sunset, Mint, Blossom, Aurora night), each with its own live wallpaper (waves, bubbles, leaves, petals, aurora and stars), a live clock and tips on the desktop, and a Calm motion switch. The choice is kept in the browser's local storage, as a convenience for that viewer only. | People asked for livelier animation and a choice of pleasant colours. |
| 2026-10-19 | The app is a desktop: icons, draggable windows (minimize, maximize, close), a taskbar with Start, an ask box and a clock, on an animated ocean-blue wallpaper with a dark version. Each app (Translator, Assistant, Help, Privacy, Terms) is a window; a minimized call keeps running; on a phone every window fills the screen. | People asked for a Windows-like, animated app where everything is an icon. |
| 2026-10-19 | The Assistant replaces the in-call Ask panel. It is a chat that keeps its history in the page only, answers any question, uses Google Search grounding when the answer needs the web, reads the running call's transcript, and carries out app commands through Gemini function calling. The browser says which commands are possible at that moment and the server only returns those, checked. Starting a conversation still needs the person to press start and say hello, and sharing the meeting's sound still needs their click, because consent and the browser's screen-share prompt require it. | One assistant that answers and does the work, without letting the model act beyond what the person can do on screen. |
| 2026-10-19 | An assistant panel in the call answers questions about the conversation (summary, action items, who said what) in the reader's language. The browser sends the transcript it shows with each question; the server keeps nothing and uses the same `GEMINI_MODEL`. It answers only from the transcript and ignores instructions spoken in it. | People asked for help during meetings without anything being stored. |
| 2026-10-19 | Each sentence goes to Gemini with the last four sentences of the conversation as context, marked as never to be transcribed or translated. | Names and topic words were misheard when each sentence was heard on its own. |
| 2026-10-19 | The backend starts the Cloudflare quick tunnel itself when a person on this computer starts a two-device conversation, and the invite link uses the public address it gets; the tunnel stays open while the backend runs. A person who opened the app through a tunnel or proxy keeps that address. `PUBLIC_URL` replaces the tunnel once the app is hosted somewhere. | Starting the tunnel by hand in a third window, then having to open the app through its address, was the step people got wrong; the invite link must just work from localhost. |
| 2026-10-19 | Meetings: the app captions an online meeting (Meet, Teams, Zoom) for the one person using it. The browser shares the meeting's tab or screen sound (`B`) and the microphone (`A`); the meeting's sentences are shown in that person's language and their own words as spoken; nothing is sent into the meeting, so no virtual microphone is needed. Speaking into the meeting in a translated voice is not planned. | Captions and a transcript are what people asked for; sending a voice into the meeting needs extra software on the laptop and a voice model, and most meetings already carry the person's own voice. |
| 2026-10-19 | Dropped connections come back by themselves: the browser pings every 5 s and reconnects with growing waits for up to five minutes, the server keeps a session or room for a device that is gone (10 minutes, 30 for a room), a newer connection takes over from an older one, and the other person sees "waiting" instead of losing the call. A conversation ends only when someone presses End. | A phone switching from Wi-Fi to mobile data ended every call. |
| 2026-10-19 | Through a public link, starting a conversation needs a host key that the backend prints at startup (new on every start, kept only in memory); invited guests are let in by their invite link. Requests from the backend's own computer need no key. | Anyone who found the tunnel address could spend the owner's free Gemini quota. A key in the terminal needs no accounts, files or settings. |
| 2026-10-19 | Gemini calls are tried once more after a short wait when Gemini is busy or briefly unreachable; long suggested waits are reported instead. Each sentence's timings (waiting, understanding, voice) are logged without its words. | One busy answer lost a whole sentence; timings show where the delay really is before anything is tuned. |
| 2026-10-19 | The echo filter ignores a sentence only while a voice is playing to that person (the browser reports each voice it played, whether the server's or its own) and the words repeat it; nothing is ignored with captions only. The API accepts two people with the same language (then nothing is translated between them); the setup screens ask for two different languages because there would be nothing to translate. | Short real replies such as "no" or "okay" were being dropped, and the same-language rule differed between the API and the screens. |
| 2026-10-19 | The conversation screen works like a video call: a tile per person that glows while they speak, a caption strip in the reader's language, a transcript panel with text and subtitle (SRT) downloads made in the browser, and a control bar for mute, voice or captions only, settings and end. In settings each person picks their language mid-call, a natural Gemini voice (listed live from Google's Voices API) or the browser's own voice, and the speed. Captions arrive once a sentence ends; word-by-word captions would need Google's streaming service and are not planned yet. | People asked for a familiar, Meet-style call with one consistent voice they choose. |
| 2026-10-18 | Two people on different devices: the host starts a room and shares an invite link; each device sends only its own microphone and plays only the translations for its person, and both see the whole chat. The laptop serves the app and the API at one address, and a free Cloudflare quick tunnel makes it reachable over https. Phone calls through the phone network and listening with the screen off need a native phone app, planned later. | People want to talk to someone who is not in the same room, for free. Browsers cannot reach phone-call audio or keep the microphone on in the background on phones. |
| 2026-10-18 | Setting up is spoken: an assistant asks each person to say hello, finds their language with one Gemini request each (`POST /api/languages/detect`), then starts the conversation. Picking from a list stays as a fallback. The conversation is one chat with each person's bubbles on their own side and the translation under each. A sentence that is nearly all of a translation from the last 12 s is ignored, and the microphone reopens 0.6 s after a voice ends. | Faster, friendlier setup with nothing to type. On laptop speakers the app was hearing its own voice and translating it back. |
| 2026-10-18 | Speed first: a sentence ends after about 1 s of silence (was 1.5 s), and the server learns the room's background sound so fans or traffic do not keep a sentence open. The browser speaks a translation with its own voice when it has one for that language, which starts at once; the Gemini voice is made only for languages the browser cannot speak. A voice does not start while someone is speaking (waiting at most 15 s), so a reply is not cut off; a reply that begins in the fraction of a second before the server notices it can still be cut. In call mode the server voice always stays on, because the other person can hear only that voice. | Waiting for the Gemini voice added about 4 s per sentence, and people started replying before it played, which cut their reply off. |
| 2026-10-18 | Call mode: the app translates calls that run in a browser tab (Google Meet, or Zoom and Teams on the web). The browser sends this device's microphone (A) and the call tab's sound (B) as two tagged sources; the speaker is the source. The other person hears only the translation, through a free virtual microphone (VB-Cable) that the call app uses, so every sentence is voiced for them, even in their own language, and call mode needs the server voice. The browser part is built by the frontend developer. | Uses standard browser features (tab audio capture and output-device choice), with nothing to install for the other person; knowing the source removes speaker guessing. |
| 2026-10-18 | Each request tells the model the two people's chosen languages as a hint: the speaker most likely uses one of them, but any language is still accepted. The model is told never to guess unclear words and never to answer with anything but the translation. The model also says, for each person's language, whether it is the language spoken; that answer is used only when no language code or name matches. A translation that repeats the words spoken (ignoring punctuation, spacing and case) is accepted only for a single word of at most 20 characters, such as a name or "No."; anything longer is reported as not translated. Known gap: a short sentence in a script written without spaces (Chinese, Japanese, Thai) counts as one word. | A live check heard one Telugu clip as Nepali and returned a reply instead of a translation; the conversation's languages are already known. |
| 2026-10-18 | Translations are spoken by a Gemini voice model (`GEMINI_TTS_MODEL`) live over HTTP, in a separate queue so voices never delay captions; the audio goes to the browser in memory and is never saved. When a voice cannot be made, the browser speaks with its own voice or shows captions only. | Same voice quality for any language on every computer; the browser fallback keeps the conversation going when the free voice limit is reached. |
| 2026-10-18 | Speech recognition and translation use the Gemini API free tier through Google's `google-genai` SDK: one request per utterance returns the transcript, detected language and translation. The model is set by `GEMINI_MODEL` and chosen with `scripts/benchmark.py`. | One request per sentence saves free quota; the provider sits behind the `SpeechTranslator` interface so a local model can replace it. |
| 2026-10-18 | No fixed language list. Any ISO 639 code is accepted; the speech service reports the detected code and its name live, and the frontend builds the picker from the browser's `Intl.DisplayNames`. `GET /api/languages` is removed. | Any language Gemini can handle works without a list to maintain. Quality on rare languages is unmeasured until used. |
| 2026-10-18 | Nothing is recorded or kept longer than needed: no debug audio files, each utterance's audio is dropped once translated, a session leaves memory when its live channel opens (one channel per session), unopened sessions expire after 10 minutes, settings are read without a cache, and model names come only from `GEMINI_MODEL` and `GEMINI_TTS_MODEL`. | Everything is live; memory stays flat however long the backend runs. |
| 2026-10-18 | Models are compared live: `scripts/benchmark.py` streams real speech from Google's FLEURS dataset (CC BY 4.0) into Gemini one language at a time and prints the results; the model list comes live from Google (`--list-models`) and the default is `GEMINI_MODEL`. Nothing is downloaded to disk or saved. | Same sentences in about 100 languages with correct transcripts, so detection, transcription and translation are checked without recording by hand. |
| 2026-10-18 | Free-tier use is accepted for testing even though Google may use the content to improve its products. Avoid private conversations while on the free tier. | Cost requirement; revisit before real use. |
| 2026-10-18 | Automatic checks on GitHub Actions for every pull request: backend tests and lint on Linux and Windows, frontend type check, tests and build. | Pull requests are verified before merging, including Windows-only problems. |
| 2026-10-18 | Both developers work on branches and merge through pull requests. The backend developer (project owner) owns `backend/` and merges all pull requests; the frontend developer owns `frontend/`. | Parallel work without editing the same files, with every change reviewed. |
| 2026-10-18 | The WebSocket checks the browser's `Origin` and only accepts the configured frontend address (close code 4403). | Stops other websites from opening the live channel. |
| 2026-10-18 | Hands-free listening replaces the talk buttons: the browser streams the microphone and the server ends each sentence after about 1.5 s of silence (30 s at most). Speech with no recognisable words is ignored quietly and listening continues; only End stops the conversation. | People talk naturally without pressing anything. |
| 2026-10-18 | Who spoke is decided by the language heard: one live request returns the transcript and a translation into each person's language. A match with one person's language makes them the speaker and the other the listener; a third language is translated for both; a language both chose needs no translation. | Works on one shared device with no buttons; one request per sentence saves free quota. |
| 2026-10-18 | **Any spoken language in, the listener's chosen language out.** Each participant picks a preferred language. Speech language is detected automatically. Translation is skipped when the speech is already in the listener's language. | Core product requirement. Telugu and English are only the first test pair. |
| 2026-10-18 | Free services only: Gemini API free tier, local models (Whisper) and browser voices. | Cost requirement. Paid services need the owner's approval. |
| 2026-10-18 | Project lives in `C:\dev\Ai-translator`, outside OneDrive. | OneDrive syncing breaks package installs. |
| 2026-10-18 | React + TypeScript + Vite frontend; Python 3.12 + FastAPI backend; no database while nothing is stored. | Agreed stack; speech and translation libraries are Python-first. |
